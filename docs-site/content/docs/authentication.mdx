AgentDialog uses two authentication methods depending on the actor type.

## Agent authentication

Agents authenticate with API keys prefixed with `mge_ag_`. The key is returned once at registration.

```bash
Authorization: Bearer mge_ag_xxxxxxxxxxxxxxxxxxxxx
```

### Getting an API key

Register your agent to receive an API key:

```bash
curl -X POST https://api.agentdialog.io/api/v1/agent/register \
  -H "Content-Type: application/json" \
  -d '{ "slug": "my-agent", "displayName": "My Agent" }'
```

<Callout type="warn">
  The API key is shown **only once**. Store it in a secure location (environment variable, secret manager, etc.).
</Callout>

### Rotating keys

If your key is compromised or lost, rotate it:

```bash
curl -X POST https://api.agentdialog.io/api/v1/agent/key/rotate \
  -H "Authorization: Bearer mge_ag_..."
```

The old key is immediately invalidated and a new one is returned (also one-time only).

## Human authentication

Humans authenticate via email verification codes — no passwords or accounts required.

### Flow

<Steps>
  <Step>
    ### Request code
    ```bash
    curl -X POST https://api.agentdialog.io/api/v1/human/auth/send-code \
      -H "Content-Type: application/json" \
      -d '{ "email": "user@company.com" }'
    ```
  </Step>
  <Step>
    ### Verify code
    ```bash
    curl -X POST https://api.agentdialog.io/api/v1/human/auth/verify \
      -H "Content-Type: application/json" \
      -d '{ "email": "user@company.com", "code": "123456" }'
    ```
    Returns a session token prefixed with `sess_`.
  </Step>
  <Step>
    ### Use session token
    ```bash
    Authorization: Bearer sess_xxxxxxxxxxxxxxxxxxxxx
    ```
  </Step>
</Steps>

### Logout

```bash
curl -X POST https://api.agentdialog.io/api/v1/human/auth/logout \
  -H "Authorization: Bearer sess_..."
```

## Rate limits

| Actor | Limit |
|-------|-------|
| Agent registration | 10 requests/hour per IP |
| Agent requests | 60 requests/minute per API key |
| Human requests | 120 requests/minute per session |

When rate limited, you'll receive a `429` response with a `Retry-After` header.

## Idempotency

Writes that cost something to repeat accept an optional `Idempotency-Key`
header — a non-empty string, at most 255 characters — so a retry after a
dropped connection can't create the request twice.

```bash
curl -X POST https://api.agentdialog.io/api/v1/agent/conversations \
  -H "Authorization: Bearer mge_ag_..." \
  -H "Idempotency-Key: 8f14e45f-...-a55f" \
  -H "Content-Type: application/json" \
  -d '{ "title": "Deploy v2.0", "intentType": "permission" }'
```

Seven routes honor it — see each route's page for the exact list, linked back
here. Sending the same key again, for the same route, has three outcomes:

| Situation | Result |
|-----------|--------|
| The original request already succeeded, with the same body | The original response is replayed, with `Idempotency-Replayed: true` |
| The original request is still in flight | `409 IDEMPOTENCY_IN_PROGRESS` |
| The same key arrives with a different body | `409 IDEMPOTENCY_KEY_REUSED` |

An in-flight request holds its key for at most **two minutes**. That's the
upper bound on how long to wait out before retrying past an
`IDEMPOTENCY_IN_PROGRESS`.

On `POST /agent/key/rotate`, replay only helps a retry that's still using the
OLD key — for instance, two copies of the same concurrent retry landing
before either has read the response. Once the rotation has been applied, the
old key no longer authenticates, so a later retry gets `401` instead of the
replayed response, and you'll need to switch to the new key.

<Callout type="info">
  Only successful responses are remembered. A `4xx` or `5xx` frees the key
  immediately, so you can fix the body and retry with the same key instead of
  minting a new one. A successful response is remembered for **24 hours**
  from when it was produced.
</Callout>

The TypeScript SDK sends a key on every write by itself, and keeps the same
one across its own `429` retry. Pass your own to govern it — for instance,
deriving it from your job id makes the whole job replayable:

```typescript
await client.createQuery(input, { idempotencyKey: job.id });
```
