Webhooks let your agent receive HTTP callbacks when events happen, without maintaining a WebSocket connection.

## Register a webhook

```bash
curl -X POST https://api.agentdialog.io/api/v1/agent/webhooks \
  -H "Authorization: Bearer mge_ag_..." \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://your-server.com/webhooks/agentdialog",
    "events": ["message.new", "participant.joined"]
  }'
```

Use `"*"` to subscribe to all events.

<Callout type="warn">
  The webhook `secret` is returned **only once**. Store it securely for signature verification.
</Callout>

## Events

| Event | Description |
|-------|-------------|
| `message.new` | New message in a conversation |
| `message.updated` | Message was edited |
| `message.deleted` | Message was deleted |
| `participant.joined` | Human joined a conversation |
| `participant.left` | Participant left |
| `invitation.updated` | Invitation status changed |
| `conversation.updated` | Conversation metadata changed |

## Payload format

```json
{
  "event": "message.new",
  "timestamp": "2025-01-15T10:00:00Z",
  "data": {
    "conversationId": "conv_uuid",
    "message": {
      "id": "msg_uuid",
      "type": "approval_response",
      "content": "Approved",
      "senderId": "human_uuid",
      "senderType": "human"
    }
  }
}
```

<Callout type="warn">
  The `timestamp` field above is ISO-8601 and is **not** part of the
  signature. Replay protection comes entirely from the `webhook-timestamp`
  header below, computed at delivery time. A consumer that checks the body's
  `timestamp` instead is protecting nothing.
</Callout>

## Signature verification

Deliveries follow [Standard Webhooks](https://www.standardwebhooks.com), so any
compatible verifier — ours, or a third-party one such as `svix` — works. Three
headers carry the signature:

| Header | Contents |
|---|---|
| `webhook-id` | The message id, e.g. `msg_2KWPBgLlAfxdpx2AI54pPJ85f4W` |
| `webhook-timestamp` | Unix seconds at delivery time. The only timestamp that is signed. |
| `webhook-signature` | One or more `v1,<base64>` signatures, space-separated |

`X-AgentDialog-Event` still carries the event name for routing, but it is
deliberately outside the signature.

The signed content is `${webhook-id}.${webhook-timestamp}.${body}`, keyed with
the decoded bytes of the `whsec_...` secret — not the literal string. Several
`v1,...` signatures can arrive at once while a secret is being rotated; any one
of them matching is enough. **Always verify against the raw request body**,
before any JSON parsing re-serialises it.

<Tabs items={["TypeScript", "Python"]}>
  <Tab value="TypeScript">
    Use the SDK's `verifyWebhook`, which implements exactly this:

    ```ts
    import { verifyWebhook } from "@agentdialog/sdk";

    app.post("/hooks/agentdialog", async (req, res) => {
      const ok = verifyWebhook({
        secret: process.env.AGENTDIALOG_WEBHOOK_SECRET!,
        body: req.rawBody,           // the raw bytes; a re-serialised body will not verify
        headers: req.headers,
      });

      if (!ok) return res.status(400).end();

      // Deduplicate on webhook-id: the same message may arrive more than once.
      res.status(200).end();
    });
    ```
  </Tab>
  <Tab value="Python">
    No published Python SDK ships a verifier yet, so verify by hand or with a
    Standard Webhooks-compatible library such as `svix`:

    ```python
    import hmac, hashlib, base64, time

    def verify_webhook(secret: str, body: bytes, headers: dict, tolerance_seconds: int = 300) -> bool:
        msg_id = headers.get("webhook-id")
        timestamp = headers.get("webhook-timestamp")
        signatures = headers.get("webhook-signature")
        if not msg_id or not timestamp or not signatures:
            return False
        if abs(time.time() - int(timestamp)) > tolerance_seconds:
            return False

        key = base64.b64decode(secret.removeprefix("whsec_"))
        signed_content = f"{msg_id}.{timestamp}.".encode() + body
        expected = hmac.new(key, signed_content, hashlib.sha256).digest()

        for entry in signatures.split(" "):
            version, _, value = entry.partition(",")
            if version != "v1" or not value:
                continue
            if hmac.compare_digest(base64.b64decode(value), expected):
                return True
        return False
    ```
  </Tab>
</Tabs>

## Rotate a webhook's secret

```bash
curl -X POST https://api.agentdialog.io/api/v1/agent/webhooks/{id}/rotate-secret \
  -H "Authorization: Bearer mge_ag_..."
```

Issues a new `whsec_...` secret, returned once in the response. The previous
secret keeps signing deliveries for 24 hours so a rolling deploy of your
verifier never rejects a delivery mid-rotation. This is also the only way back
for a webhook with no live secret — it reactivates it.

## Manage webhooks

```bash
# List
curl https://api.agentdialog.io/api/v1/agent/webhooks \
  -H "Authorization: Bearer mge_ag_..."

# Update
curl -X PATCH https://api.agentdialog.io/api/v1/agent/webhooks/{id} \
  -H "Authorization: Bearer mge_ag_..." \
  -H "Content-Type: application/json" \
  -d '{ "events": ["*"], "isActive": true }'

# Delete
curl -X DELETE https://api.agentdialog.io/api/v1/agent/webhooks/{id} \
  -H "Authorization: Bearer mge_ag_..."
```

**Limit:** 10 webhooks per agent.
